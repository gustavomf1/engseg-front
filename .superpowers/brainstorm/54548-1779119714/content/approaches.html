Como implementar o estado dos emails manuais?

O segmented control (A) já está definido. A questão agora é como organizar o estado interno e o payload do onConfirm.

A

Dois arrays separados Recomendado

localManuaisDinamico: string[]
localManuaisPadrao: {email, checked}[]

Prós: espelha a arquitetura atual (dois grupos distintos), fácil de renderizar em cada seção separada, sem ambiguidade de tipo.
Contras: dois estados em vez de um.

No onConfirm: emailsManuais recebe a união dos dois grupos (padrão só se checked). Nenhuma mudança de interface com o backend.
B

Array unificado com tipo

localManuais: {email, tipo: 'DINAMICO'|'PADRAO', checked}[]

Prós: estado único, fácil de iterar.
Contras: renderização fica mais complexa (filtragem por tipo para cada seção); checked é irrelevante para DINAMICO (ruído no tipo).

No onConfirm: filtra os que devem ser enviados e envia em emailsManuais.
C

Padrão manual vira EmailPadrao local

localManuaisDinamico: string[]
Padrão manual injeta em emailsPadrao com flag isManual

Prós: padrão manual reutiliza toda a lógica de renderização e exclusão dos emails padrão.
Contras: mistura dados de configuração (vindos do backend) com dados locais — confuso, pode causar bugs se emailsPadrao for somente-leitura.

Não recomendado: acopla estado derivado do servidor com estado local.
